# 06 — Revisão final de frontend

Leia instruções, diagnóstico, plano, matriz, contratos e progresso. Verifique se as etapas foram efetivamente concluídas; não trate implementação parcial como finalizada.

Compare o resultado com o comportamento original e decisões aprovadas. Revise por áreas e grave checkpoints. Inclua formulários, rotas/deep links, sessão, permissões, cache, filtros/paginação, arquivos, teclado, responsividade e envio duplicado. Diferencie API simulada de integração real. Use o backend original em ambiente de testes quando disponível; sua migração não é pré-requisito.

Execute checks pertinentes e registre resultados, pré-requisitos ausentes e testes ignorados. Não declare integração real validada com base em mocks. Corrija defeitos dentro do escopo; decisões novas devem ser registradas para revisão.

Atualize matriz, progresso, validação e procedimento proposto de publicação/reversão. Registre quais evidências sustentam a conclusão e pendências impeditivas. Prepare roteiro de homologação deste projeto, independente do avanço da outra migração.

Não gere arquivos obrigatórios para a outra migração. A integração das versões migradas será uma etapa conjunta posterior. Não altere o outro repositório, não faça commit automaticamente e não publique. Pare para revisão; use o prompt 05 depois da validação.
